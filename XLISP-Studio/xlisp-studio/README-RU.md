# XLISP Studio

Оболочка для настоящего XLISP из https://github.com/dbetz/xlisp.

## Запуск на Windows 10/11

1. Распакуй **весь** архив в отдельную папку.
2. Установи Python 3.10 или новее с https://www.python.org/downloads/windows/.
   В установщике оставь включённым компонент **tcl/tk and IDLE** и включи
   **Add python.exe to PATH**. Если Python с tkinter уже установлен, повторная установка не нужна.
3. Дважды нажми **Start-Windows.bat**.

Готовый интерпретатор `engine/xlisp.exe` уже включён. Компилятор, pip-пакеты
и интернет для работы оболочки не нужны. `studio.pyw` также можно запускать напрямую.

## Что есть

- Редактор с номерами строк, подсветкой, отменой и повтором изменений.
- Копирование, вставка, вырезание, выделение всего и меню правой кнопки.
- Многострочный код и запуск только выделенного фрагмента либо всего редактора.
- Консоль с прокруткой колесом, полосой прокрутки и PageUp/PageDown.
- При прокрутке вверх новый вывод не перебрасывает тебя вниз. Есть кнопка «В конец».
- Редактируемая строка команды, история ↑/↓ и Alt+↑/↓. История последних
  300 отправок сохраняется между запусками в `%APPDATA%/XLISP-Studio/history.json`.
- Открытие/сохранение UTF-8 файлов .lsp и экспорт текста консоли.
- Отдельный процесс движка: зависший Lisp можно остановить, не закрывая редактор.
- Определения и переменные живут между отправками до остановки процесса.

## Клавиши

| Действие | Клавиши |
| --- | --- |
| Запуск кода или выделения | Ctrl+Enter в редакторе |
| Отправить команду / данные для `(read)` | Enter в нижнем поле |
| Новая строка команды | Shift+Enter |
| История команд | ↑/↓ на первой/последней строке, либо Alt+↑/↓ |
| Копировать / вставить / вырезать | Ctrl+C / Ctrl+V / Ctrl+X |
| Выделить всё | Ctrl+A |
| Отменить / повторить | Ctrl+Z / Ctrl+Y |
| Открыть / сохранить | Ctrl+O / Ctrl+S |
| Сохранить как | Ctrl+Shift+S |
| Остановить движок | F8 |
| Перезапустить движок | F5 |

Вставка сама по себе ничего не выполняет. Для запуска нажми кнопку или сочетание клавиш.

## Первый пример

В редакторе уже есть пример. Нажми Ctrl+Enter: увидишь `144` и `(1 4 9 16 25)`.
Или открой `examples/hello.lsp`; в нём также есть факториал, результат — `720`.

Это диалект XLISP 3.3 из указанного репозитория. Его исходные примеры используют
`define`; совместимость с Common Lisp, AutoLISP и старыми версиями XLISP не обещается.

## Ошибки, остановка и файлы

После ошибки оригинальный XLISP может показать `Debug ...>`. Отправь `(reset)`
в нижнем поле или выбери **Сеанс → Выйти из отладчика**. Это возвращает верхний
уровень с сохранением определений. F8 завершает процесс целиком; после F5
переменные придётся определить заново. Редактор при этом остаётся на месте.

Если код ждёт `(read)`, введи данные в нижнее поле. Отправки идут в общий поток
интерпретатора; не запускай несколько больших программ одновременно.

Рабочая папка Lisp — `engine/`, независимо от расположения открытого файла.
Для загрузки других файлов указывай абсолютный путь с `/`, например:
`(load "C:/Users/User/Documents/program.lsp")`.
При путях с кириллицей старый C-движок на Windows может не открыть файл;
загрузка содержимого через редактор и Ctrl+Enter этого пути не использует.

Ввод/вывод оболочки — UTF-8. Сам XLISP обрабатывает строки побайтно:
длина и индексация кириллицы могут отличаться от числа видимых букв.
Консоль хранит вывод в памяти до очистки; для очень большого вывода используй
сохранение в файл и очистку консоли. Не оставляй бесконечную печать без необходимости.

## Linux и пересборка

На Linux нужны Python 3.10+, tkinter и графический сеанс. Включён Linux x86_64
движок, собранный в Debian 13; если он не запускается на твоей системе:
`python3 build_engine.py`. Затем `sh Start-Linux.sh`.

Для Windows движок можно пересобрать из включённых исходников:
`python build_engine.py --windows --cc "gcc"` с 32-битным MinGW,
либо `python build_engine.py --windows --cc "zig cc -target x86-windows-gnu"`.
Используется 32-битная сборка: старый код XLISP предполагает размер long,
совпадающий с размером указателя; Windows x64 напрямую этому не соответствует.

## Исходники и проверка

`studio.pyw` — интерфейс и управление процессом.
`source/engine_main.c` — точка входа с неблокируемым для GUI процессом и
немедленным выводом в pipe; сам GUI выполняет чтение/запись в фоновых потоках.
`source/src`, `source/include`, `engine/*.lsp` — исходники и библиотеки XLISP.
`build_engine.py` — воспроизводимая команда сборки.
